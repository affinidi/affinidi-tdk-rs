# affinidi-messaging-didcomm-v1

A DIDComm **v1** (Aries RFC 0019) implementation for the Affinidi TDK, sitting
alongside [`affinidi-messaging-didcomm`](../affinidi-messaging-didcomm) (v2.1)
rather than replacing it.

Every Aries-lineage wallet — Credo and everything built on it — speaks v1 and
only v1. This crate is what lets the TDK reach them.

## Features

- **Authcrypt** (`crypto_box` + ChaCha20-Poly1305) — sender-authenticated
- **Anoncrypt** (`crypto_box_seal` + ChaCha20-Poly1305) — anonymous
- **Plaintext** messages
- **Forward/routing** (Aries RFC 0094)
- **Basic Message 1.0** (Aries RFC 0095) as the carrier protocol
- **Keys**: Ed25519 verkeys, X25519 key agreement (v1 has no curve agility)

## Optional features

- `messaging-core` — implements `MessagingProtocol` from
  `affinidi-messaging-core`, so v1 can be driven through the same surface as
  DIDComm v2.1 and TSP, and told apart by `Protocol::DIDCommV1`.

## Scope

Transport primitives only. Document validation, consumer pipelines,
error-response routing and proof verification belong to the layer above; this
crate's job ends at "here is a decrypted message body and the authenticated
identity of who sent it".

## Parity with v2.1, and where it deliberately breaks

The API mirrors the v2.1 crate module-for-module so a consumer can write
transport-agnostic code over both. Where the protocols genuinely differ, this
crate diverges rather than pretending:

| | v2.1 | v1 |
|---|---|---|
| Envelope | real JWE, JWA algorithms | JWE-shaped JSON, libsodium algorithms |
| Sender identifier | `skid`: a DID URL | a bare base58 Ed25519 verkey |
| Message headers | `id` / `type` | `@id` / `@type` |
| Payload | nested `body` | top-level members |
| Threading | `thid` / `pthid` headers | `~thread` decorator |
| Addressing | `from` / `to` headers | none — transport only |
| Unpack result | `Encrypted { authenticated: bool, sender_kid: Option<_> }` | disjoint variants |
| Signed envelopes | JWS, sign-then-encrypt | none |
| Curve agility | 5 curves | X25519 only |

### The unpack result

Read this before using the crate. v1 anoncrypt has no authenticated sender, so a
consumer that mistakes it for an authenticated message has nobody to route an
error response to — and replying anyway turns the agent into an identity oracle.
`UnpackResult` therefore makes the cases disjoint variants with no
`Option<Did>` to unwrap carelessly:

```rust
use affinidi_messaging_didcomm_v1::{DIDCommV1Agent, UnpackResult};

# fn demo(agent: &DIDCommV1Agent, packed: &str) -> Result<(), Box<dyn std::error::Error>> {
// The safe path — anything not attributably authcrypt is rejected here.
let authenticated = agent.unpack(packed)?.require_authenticated()?;
println!("{} -> {}", authenticated.sender, authenticated.recipient);

// Or match, if the other states need handling.
match agent.unpack(packed)? {
    UnpackResult::Authcrypt { sender, .. } => println!("from {sender}"),
    UnpackResult::AuthcryptUnknownSender { sender_verkey, .. } => {
        println!("authenticated by {sender_verkey}, but bound to no DID")
    }
    UnpackResult::Anoncrypt { .. } => println!("anonymous — do not reply"),
    UnpackResult::Plaintext(_) => println!("unprotected"),
    _ => {}
}
# Ok(())
# }
```

`AuthcryptUnknownSender` has no v2 counterpart: a v2 envelope names its sender
with a DID URL, so the DID always comes out of the envelope. A v1 envelope names
a raw key, and the key → DID binding is connection state this crate must be told
about.

## Interop

Tested against **Credo 0.6.3 / askar 0.4.3**, the reference v1 implementation,
in both directions. Committed fixtures generated by a live Credo agent are
opened in CI by `tests/credo_interop.rs`; the reverse direction runs through the
developer harness in [`interop/didcomm-v1`](../../../interop/didcomm-v1).

## Wire-format hazards

Three details are easy to get wrong and produce envelopes no Aries agent can
open. All three are pinned by tests:

1. **`enc` lies.** The protected header always says `xchacha20poly1305_ietf`,
   but the algorithm is ChaCha20-Poly1305 IETF with a **12-byte** nonce, not
   XChaCha20 with a 24-byte one.
2. **libsodium byte order.** `crypto_box` output is `MAC || ciphertext`; the
   RustCrypto AEAD default appends the tag instead.
3. **Two type URI prefixes.** `did:sov:BzCbsNYhMrjHiqZDTUASHg;spec/…` and
   `https://didcomm.org/…` are interchangeable, and which one a peer sends is
   its configuration. Compare with `types_match`, never `==`.
